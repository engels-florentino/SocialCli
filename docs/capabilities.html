Capabilities, permissions and limits

SocialCli SaaS candidate · implementation scope, October 14, 2026.

A supported command is not proof of access. Provider app eligibility/review, creator consent, token grants, actor role and object eligibility all matter. Adding permissions in a developer dashboard does not add them to existing tokens; reconnect with the requested optional access and have the creator consent. --analytics and --management request separate optional permissions.

Required permissions above describe the supported integration, not a claim that any connected account currently holds them. Meta Business Manager roles and features can impose additional requirements. External creators require the provider's applicable Advanced Access, app verification/review or production approval. The hosted pilot status is documented in connections. Public GitHub availability does not establish production approval.

Results and recovery

stats --json and inbox --json produce version 1 reports, with progress on stderr. For aggregate stats/inbox/report, exit 0 is complete, 3 is partial, 1 is failure, and 2 is an invalid invocation. Other read commands retain their documented exit contracts. Parser errors use standard CLI usage on stderr. Existing successful JSON schemas remain intact. Snapshots retain provenance when previous data is reused. Complete watermarks cover only the exact scope read; missing rows never prove deletion globally.

Direct Meta readback checks returned ID, actor, parent/media and exact text. No guessed numeric/composite ID transformation or text-only match is proof. A bounded readback window can leave a successful remote write uncertain. Inspect its journal and reconcile; do not create another proposal just to repeat it. Synthetic tests verify these safeguards but do not prove live eventual-consistency behavior or provider production access.

Authenticated encrypted-file capability storage is an explicit Linux/macOS option. Use one protected external store per brand, a separate external key, verified migration and recoverable rotation. Default remains the OS keyring. Provider application secrets and refresh tokens stay on the shared service.

Provider references

Contracts were checked using current official documentation during implementation: Facebook comment, Facebook replies, Instagram comment replies, YouTube comments, YouTube video ratings, TikTok app review. Provider policy and availability can change; these references do not certify a particular app or account.

Facebook comment likes

Use explicit quoted IDs in a Meta proposal. Do not pass a comment ID as target_id: that field is the owned Page post; comment_id selects its comment.

action: like
target_id: "123_789"
comment_id: "789_800"

socialcli meta prepare --file like-comment.yaml --platform facebook --brand MyBrand --dry-run

Review the full saved proposal and obtain approval before applying. The preview includes the comment text, media ID and observed Page like state. An unavailable has_liked state or unverified target stops preparation. Use action: unlike for a separately approved removal. Distinct comments on the same post can be children of one community batch; duplicate targets are rejected.

inbox shares its total timeout among configured supported platforms so one slow provider cannot consume the entire budget. Meta enumeration requests only IDs and ownership; later request failures retain earlier verified media. A partial report with zero observed comments does not establish an empty inbox. YouTube stats retains fetched account/video metrics when optional enrichment or audience reads fail, records warnings, and reports partial JSON coverage.

Unknown Meta authors are represented by author_id: null; coverage counts them as unknown_author. This preserves visible comments without attributing them to a person or proving own authorship. Own-comment edit/delete checks remain strict. YouTube comments_disabled means the video disables comments, not that the account needs to reconnect.

Facebook comment IDs and deletion receipts

Facebook may return a video-scoped comment ID from creation and a different post-scoped ID in the owned video's comments edge. Follow-up reads and proposals resolve this only through the exact direct response and one matching specific official comment permalink, with consistent author, text and target. The complete preview shows the observed canonical target; matching numeric suffixes alone is never sufficient.

A successful deletion receipt is distinct from independent proof of absence. Meta video deletion retains accepted_unverifiable; comment deletion retains applied_unverified. The output diagnostic operation_accepted_unverified means the provider accepted the request. Preserve the receipt and do not repeat the write. A generic missing/inaccessible object response is not definitive deletion evidence. Comment apply still exits 1 when the effect cannot be independently verified; agents must inspect the status and diagnostic instead of reporting a provider rejection or repeatedly reconciling an inherently unverifiable result.
